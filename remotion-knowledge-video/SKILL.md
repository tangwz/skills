# Remotion 知识视频

把同一频道的视频做成稳定的视觉家族，同时让每一期的图解服务自己的知识命题。品牌配置决定视觉；口播决定时间预算和叙事进度，图解与动效在该预算内编排。与用户沟通使用中文，只有必要术语使用英文。

## 1. 确认范围与现有约束

先读目标项目的 `AGENTS.md`、`package.json`、Composition 注册、现有主题与字体加载代码，查看相关视频的代表性画面。区分任务类型：

- **完整新一期**：安排内容开场、知识图解和结尾总结，可以使用统一片头片尾。
- **讲解片段或系列中间一节**：默认不插入频道片头片尾；适配用户指定的旧片段时保持既有时长和接口。
- **整篇逐字稿批量制作**：读取 [逐字稿分段与批量输出](references/batch-transcripts.md)。按正文顶层 Markdown 分隔线拆分，按原文顺序为每个包含有效口播的非空段创建独立动画和 Composition；逐段匹配口播，复用共用品牌层。只有标题、镜头提示或代码示例的无口播段单独标记，默认不制作；用户明确要求无口播画面时，另按指定时长和用途安排。仅在用户要求编码或交付视频文件时逐段导出；只要求代码或预览时不编码。
- **品牌或风格调整**：修改用户指定的共用配置或组件，并检查它们影响的代表性画面。
- **旧视频适配**：保留讲解文案、公式、数据、音频和关键时序，只在已授权范围内调整视觉。

新对话（session）默认新建独立的内容组件和动画，使用未占用的文件名、导出名和 Composition ID，新增注册并保留已有作品。相似主题或当前打开的旧预览不代表要覆盖旧作。同一对话可以继续迭代本次创建的作品；用户明确指定修改、修复、继续编辑或替换某个已有作品时，才按指定范围改动它。

用户的明确要求与项目规则优先于默认风格。先利用可读材料补齐信息，只对影响主要方案的缺失项提问。频道名称和 Logo 未提供时按空值处理，省略对应元素；这不阻碍图解制作。

字幕是否显示、是否生成字幕文件及哪些内容允许修改，由目标项目规则和本次请求决定。定位实际控制开关与数据来源，不假设项目存在特定文件或采用同一字幕策略。

## 2. 建立一份可复用的品牌配置

读取 [视觉与品牌规范](references/visual-identity.md)。定位项目已有的品牌配置和组件；有就复用，不创建第二套同名职责。没有时，从 [组件模板](assets/template/) 复制所需文件到项目的 `src/video-brand/`，把该目录作为今后各期共用的实现来源：

- `video-style.ts`：色板、字体角色、背景、字号、安全区和动效参数。
- `video-brand.ts`：频道名称、Logo 的 public 相对路径、频道短语、结尾文案。
- `VideoChrome.tsx`：背景、品牌标记、字卡、内容面板、片头与片尾。
- `grid-motion.ts`：移动背景的纯时序计算，由背景组件引用，复制时一并保留。
- `end-card-timing.ts`：片尾、稳定区与入场的整数帧计算，由片尾和预览引用，复制时一并保留。
- `BrandPreview.tsx`：仅在建立品牌或验证共用组件时复制；通过 `content` props 注入样片文案。

模板是启动资源，不是每期或每个 session 复制一套的要求。单期内容通过 props 和自己的场景组件接入共用层；单期风格差异通过 props 或局部配置实现，仅在用户请求共用品牌或风格调整时修改共用层。首次接入或跨项目复用时读取 [项目接入](references/project-integration.md)，按目标项目的实际入口、字体、资源和画布适配，不引用原项目源码或本机绝对路径。

配置未确定时使用模板默认风格，并在交付时说明假设。现有频道配置优先；有意改变风格时在目标项目配置中落地，不静默改动这个技能的默认资源。Logo 只使用用户指定的频道素材；产品、论文或模型 Logo 是内容素材。

## 3. 按口播确定时间预算，再设计画面与动效

读取 [制作与验收](references/production.md)。涉及口播稿、录音或音画节奏时，再读取 [口播与时间轴对齐](references/narration-timing.md)：已有录音或用户确认的时码优先；只有稿件时按实际念法及个人语速估算，说明依据和范围。先建立口播段落、时间区间与关键讲解词的对应关系，再分配场景和动作。不能仅凑齐总时长，也不能按固定场景秒数或动画步骤累加片长。旧作品仅在本次授权调整时序时重新编排。

整篇批量制作先拆分原稿，再为每个有效口播段独立建立时间预算和 Composition；一段内可以有多个场景，但场景切换不能代替独立作品。无口播段仅在用户明确要求时制作，不捏造语音时长。用户要求视频文件时，每个制作段另有独立输出。段落之间默认不重复添加频道片头片尾，不挪用相邻段的口播时间。

提炼本期一个核心问题和结论，为每场景选择能解释关系的布局：机制流程、左右对照、尺度/数量变化、因果链、空间关系或公式推导。先定稿静态画面，再在对应口播区间内安排动效，让观众知道当前焦点、变化方向及其意义。

复用背景与品牌锚点，但不要把所有主题都做成终端或等宽卡片墙。自然科学优先画对象及关系，算法优先画数据流和状态；必要的来源说明属于画面内容。

新视频默认采用 60 fps，可在共用配置中修改；注册 Composition 时读取该配置。与相机素材混剪时核实素材及最终剪辑时间线的实际帧率，避免把 59.94 fps 和 60 fps 当成相同值。旧视频适配保留原帧率，仅在用户明确要求迁移时重新换算完整时间轴。

把片头、正文、片尾、转场和稳定区纳入同一时间预算；稿内已有开场或总结时与口播重合，不机械额外添加品牌时长。以 `Math.round(seconds * fps)` 换算内部绝对边界，再用相邻边界之差得到区间帧数，避免累积漂移；有录音时按实际挂载起点向上取整最终覆盖帧数，防止截掉不足一帧的尾音。动效按秒定义，明确区分 `Sequence` 局部帧与 Composition 全局帧。末尾留出可读的稳定结论，优先放在总结口播或已有尾部停顿内。

事实、数值或术语存在疑问时核验适当来源，再固定文案。这个技能不把未经确认的类比或简化结论变成事实。

## 4. 用 Remotion 实现

按需使用可用的 `remotion-best-practices`；不存在时根据目标项目版本查官方文档，保留此处的实现边界。使用项目已有依赖和字体加载路径，避免为品牌层额外安装媒体、动效或字体包。

动画由 Remotion 帧驱动。不要使用 CSS animation/transition、真实时钟或非确定性随机效果。资源放在 `public/`，用 `staticFile()` 与 `Img` 引用；字体加载失败应显式报错，不能用不同系统字体悄悄完成最终渲染。

新视频正常注册 Composition；样片可使用独立临时入口，避免污染用户原有注册。旧视频适配按请求控制影响面，不自动迁移整个作品库。

## 5. 验收与交付

检查开场、正文关系建立、核心变化和结尾稳定等关键帧。修改共用组件时至少比较两种内容长度或布局；为复杂时序或数学计算验证边界，不为文档措辞或简单样式编写脆弱测试。

交付包含：可编辑的配置/组件位置、Composition ID、预览或关键帧、验证方式及尚未确定的品牌项。口播视频另交付逐段时序表、口播时长依据、视频总长与差值；区分实测对齐和待录音校准的估算。检查开场、中段、结尾的讲解词与动作是否对应，以及背景、字体、品牌布局、语义色和结尾可读性。仅报告有证据的结果；未渲染或未听录音时明确说明。

批量任务按原稿顺序交付“源段 → Composition → 输出文件 → 时长 → 完成状态”的清单。要求生成视频文件时逐个完成独立编码并核对文件可播放；仅要求代码或预览时按该范围交付，不把未编码的路径列为已完成文件。

改动默认保存到本地。发布、发送、购买素材或生成旁白需要相应任务授权；创建视觉技能不隐含这些动作。

## 示例请求与回归

可直接使用：`使用 $remotion-knowledge-video，为本期主题制作一段延续频道风格的 Remotion 科普视频。`

[evals/evals.json](evals/evals.json) 包含新片、旧片适配、共用风格调整、口播估时与时码对齐，以及逐字稿批量输出示例。按产物的分段与独立输出、时长、口播进度、背景连续性、结尾静止、品牌布局及配置传播结果独立评分，允许等价实现。仅执行或维护评测时读取 [评分说明](evals/evaluation.md)；日常视频制作无需读取。示例的项目约束属于各自输入，不是其他项目的默认规则；旧分数不沿用到修改后的断言。
