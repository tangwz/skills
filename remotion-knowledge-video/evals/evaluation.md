# 行为评测的验收证据

本页供评测组织者与评分者使用，配合本目录的 `evals.json`；制作视频时无需读取。每条断言独立评分，检查产物行为，允许不同的组件、配置接口和等价实现。

## 对照输入与评分边界

两组产物生成 agent 收到相同的用户提示词、项目材料、依赖版本与资源。案例 2 和 4 的 `files` 指向冻结输入项目；复制到各自隔离工作区后再执行，不能让一组修改另一组的输入。新片案例 1 和 3 使用相同的空白 Remotion 项目和已安装依赖。只有使用技能的一组额外得到技能及其资源；该技能快照排除 `evals/` 目录，输入项目另行复制。两组都不读取 `expected_output`、`expectations` 或本页。

提示词可以说明用户需要的时长、静止阅读时间、布局效果和验收交付物，不指定组件名称或实现方式。评分前不假定基线失败；检查基线的等价实现和使用模板的实现采用同一标准。

`KnowledgeBackground`、`EpisodeOpener`、`EpisodeEndCard`、`BrandMark`、`showBackground` 和 `resolveVideoStyle` 均不是质量门槛。一个外层背景实例是推荐实现；按全局时间计算而保持同一可见背景的其他实现也可通过。是否采用模板、背景实例数量、是否使用 `Math.round(seconds * fps)` 可另记为**不计分的实现诊断**，不得纳入质量通过率。

## 证据与独立判断

按断言顺序记录对应文件、实际调用位置、检查输出或具体方案片段。一条失败不自动使相邻断言失败。例如背景在静止区漂移而前景稳定，应分别记为失败、通过；没有沿用模板名字不构成失败。

- **代码证据**：追溯到注册的 Composition 和实际渲染组件消费的状态。未被调用的示例、未消费的常数或注释中的承诺不证明行为。
- **可运行检查**：运行交付的检查，核对输入与实际接入点，记录覆盖范围及输出。检查本身缺失或不可运行时，只影响依赖该证据的判断；其他已有充分证据的断言仍单独评分。
- **方案证据**：案例 2 仅检查具体拟议改动和复查方法，不要求执行方案或取得渲染结果。
- **渲染证据**：布局以实际排版后的元素边界或关键帧为依据。只声明一组互不相交矩形却没有用于标题、图解和标记的布局，不证明不遮挡。

若证据不足，记录“未证实”及原因；采用布尔汇总格式时记为未通过，但不要将其描述成已观察到的行为错误。没有渲染时，逐帧状态检查证明计算层行为，不能冒充像素或字体质量验收。若运行环境缺依赖或资源而阻止验证，先修复共同环境或将该轮记为无效，不将单组环境问题解释为技能效果。

两组的布局证据，以及各自修改前后的对比，必须来自同机或相同操作系统、浏览器版本及实际字体文件与字重的环境，并保持画布尺寸、缩放和设备像素比一致。记录实际字体名称、版本或文件哈希；相同的 CSS 字体栈不代表相同的字体环境。`shared-style` 的英文保留 Arial，中文使用宋体，正文 400、标题/副标题/强调 700。渲染前确认 400/700 实际映射的字体及是否使用合成粗体，保证两组映射与合成策略一致且没有字体家族的静默回退；不要求宋体一定具备独立粗体文件。宋体在 macOS 和 Windows 上的不同实现不能直接混作一轮对照。条件不一致时应统一环境后重新取得证据，不据此评分。

## 新片：案例 1 与 3

**帧率与时长**：交付的正式默认帧率为题目要求的 60 fps；验收时从同一配置分别设置 30 和 60 fps，检查实际注册 fps、总帧数及场景整数帧区间。总时长误差不超过该帧率的一帧。分别判断场景是否覆盖所有帧、重叠是否仅用于明确计划的转场；允许交叉淡化等合法重叠，不要求特定的场景切换组件。比较开场、正文主要动作和收尾的同一动效里程碑，时间偏差不超过较低帧率的一帧。接受能满足这些结果的等价取整和时序表达式，不以特定源码写法评分。

**背景连续**：沿实际消费的背景状态检查每个场景边界前后帧，核对它们属于同一条全局时间轨迹；正常移动中的邻帧不要求相等。局部帧重置导致位移跳回起点，或叠加不同相位导致可见突变，属于不连续。周期网格的取模坐标可以数值跳变但视觉连续，应按纹理周期或渲染结果判断。额外记录静止区之前两个不同时间的背景样本，确认题目要求的移动实际存在。

**结尾静止**：分别检查背景和前景，遍历最后 1.5 秒的每一帧，与首个静止帧比较。前景检查覆盖最终画面实际使用的位置、透明度、变换、文本及其他逐帧值；完整图层像素比较也可作为证据。检查必须连接实际渲染逻辑，不接受无关常数函数。只比较两端不足以证明中间静止；这个覆盖规则分别用于背景与前景断言，不把二者合成一项。

**品牌布局**：正式身份为空，使用隔离的测试标记复查有标记分支；测试标记不写回正式配置。案例 1 使用实际配置支持的标记尺寸；案例 3 使用题目中的 300×90 像素标记。选择足够长、能触发原版式换行或边界问题的标题，记录其完整排版边界与图解边界。分别判断标题和标记之间是否有实际正间距、图解是否不被标记遮挡；间距可以来自配置、容器排版或实际测量，不要求某个字段名。移除标记后检查正文没有仅为缺失标记保留的空白。允许使用横向或纵向品牌区域，不强制正文通过缩减宽度避让。

新片不要求完整视频编码。关键帧、浏览器测量或与真实布局相连的可运行检查可提供布局证据；评分记录应明确所用证据的层次。

## 旧片方案：案例 2

冻结项目的注册、帧率、场景边界、背景来源、字体和字幕接口是对照依据。方案保持原 30 fps、660 帧及全部讲解边界，不因新片默认值重算已有帧数据。字幕资产以输入清单对照，不要求新生成字幕。

本次只授权原结构内的背景和语义色接线。评分不要求将背景迁移到外层，不要求为未来频道标记预留区域，也不要求新增片头、片尾或静止区。另列的可选建议不等于本次拟议改动；不要据此判定越界，但应区分建议和待执行片段。产品 Logo 的内容用途保持不变。

## 共用风格调整：案例 4

分别追溯两个已注册视频及从 starter 初始化的验收预览，确认它们实际消费指定速度和主网格透明度。不能只看到一个配置文件出现新值就判定所有消费者生效。提示词已授权单独新增验收代码；它不属于“正式风格只改两个值”的限制范围，不能据此判断越界。

局部覆盖独立检查；未覆盖的嵌套属性应继承共用值。接受现有合并实现或任何等价机制，不要求某个合并函数名称。starter 验收检查新建消费者的结果，不要求文件字节相等。

代表性画面使用输入项目现有时间轴，覆盖每个视频的开场、正文和结尾，对比修改前后。布局检查使用实际长标题及频道标记；内容与时间轴分别和输入快照比较。复查可以用关键帧或实际渲染树的可运行状态、布局测量，不要求完整视频编码。

## 结果记录

每轮保存 `evals.json` 内容哈希、技能版本或资源哈希、输入项目与依赖清单、两组产物位置、独立断言结果及证据。实现诊断单独保存，不加入质量分数。

按案例报告通过数和总数；如需总体指标，明确按断言汇总还是对案例通过率取平均，避免条目更多的案例无意获得更大权重。必要时另做盲评判断画面是否清楚、风格是否统一；这些主观结果与行为断言分开解释。

`historical-evaluation.json` 的 15/15 对 15/15，以及任何使用前一版 API 断言的分数，均属于旧口径，不重新标注为本轮成绩。修改断言后需要独立对照运行才有新成绩；不能预设技能胜出，也不能为制造差距修改已观察到的结果。
