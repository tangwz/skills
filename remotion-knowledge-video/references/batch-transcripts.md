# 逐字稿分段与批量输出

整篇逐字稿按 Markdown 分隔线拆成多个独立作品：每个包含有效口播的非空原稿段对应自己的内容动画、Composition 和从零开始的时间轴。无口播段单独标记，只有用户明确要求无口播画面时才制作，不捏造语音时长。仅在用户要求编码或交付视频文件时，为每个制作段生成独立输出文件；只要求代码或预览时不编码。一段内可以有多个 `Sequence`；将所有段只放进一个长 Composition，或只导出一个合集，不满足多文件请求。

## 识别分隔线并保留原稿

默认使用正文顶层的 Markdown 分隔线，例如独占一行的 `---`、`***`、`___`；推荐分隔线上下留空行。没有分隔线时作为一个视频处理。用户指定其他边界时以其要求为准。

```markdown
# Expansion

First narration block.

---

# Activation

Second narration block.

---

# Projection

Third narration block.
```

按 [CommonMark 的块结构](https://spec.commonmark.org/0.31.2/#thematic-breaks) 识别分隔线，优先使用环境已有的 Markdown 解析器及源位置。文件头须有明确的元数据声明或符合项目已知的元数据字段与值类型，才能作为 front matter；不能仅因文件以 `---` 开头或能解析成 YAML 映射，就将首段口播吞为元数据。回归示例只自动识别由非空字符串 `title`、`language` 字段组成的映射；`Speaker: First sentence` 或混有口播字段的映射仍保留为正文。其他元数据按项目约定确认，不随意扩大自动识别范围。围栏/缩进代码块、HTML 块、引用或列表内部的横线，以及 Setext 标题下划线不作为顶层视频边界。不能只用全局字符串 `split("---")`。保留原始文本，按分隔线源位置切片；渲染后的 HTML 或改写后的摘要不能代替原稿。

连续分隔线或首尾分隔线产生的空段不注册、不编码，清单中注明已跳过。没有口播、仅有标题/镜头提示/代码示例的段落单独标记；除非用户要求无口播画面，不为它捏造语音时长。不能静默丢弃有口播内容的短段，或自行合并相邻有效段。

部分解析器会把开头的 `---` 到代码围栏里的下一条横线误猜成 front matter。核对元数据声明或已知字段后再决定是否跳过该节点；不是元数据时，使用不启用 front matter 扩展的正文解析，或在解析副本中按等长顶层横线消除误判，仍从原稿源位置切片。至少复查“开头分隔线、无 YAML、代码中有横线”和“首段口播恰好是合法 YAML 映射”两种情况，不能只验证带合法文件头的稿件。

原稿中的标题、镜头提示和代码示例照常保留用于制作，但仅实际朗读的内容进入估时。不要自动补上承上启下的口播、改稿、调整段落顺序或将一段的结论提前放进另一段。

## 先建立批次清单

为本次新作品选择未占用的批次名称；按原文顺序使用稳定编号，例如 `Topic-01`、`Topic-02`、`Topic-03`。新 session 的同主题批次使用新名称或变体后缀，不覆盖旧组件、注册或输出。共用品牌层只复用一份；各段有自己的内容组件与时序，可使用合理的共享内容辅助函数。

批次清单沿用项目的数据格式，至少记录：

| 信息                               | 用途                               |
| ---------------------------------- | ---------------------------------- |
| 顺序、段落编号、原稿源区间与原文   | 核对无漏段、重复或跨段混入         |
| 内容组件、Composition ID、输出路径 | 一段对应一个独立可预览、可编码作品 |
| 时长依据、预计或确认口播时长、帧数 | 各段独立匹配口播                   |
| 录音来源区间与片内偏移（如适用）   | 区分整篇录音时间与片内时间         |
| 预览/编码状态与实际文件时长        | 区分计划路径与已完成产物           |

同一 session 继续修改本批次时沿用编号和对应关系。恢复一次渲染批次前，核对完整有序计划与原版本相同，只重试失败段并保留已完成的其他文件。新增、删除、重排段落或修改计划时，使用新的输出批次目录，避免混入旧版产物；内容组件与 Composition 编号仍可沿用本 session 的对应关系。

## 每段独立匹配口播

逐段应用 [口播与时间轴对齐](narration-timing.md)。没有录音时按各段实际念法、语速与停顿分别估时，不能把整篇总长平均分配，或先做一个总时间轴再按等长片段切割。各段默认复用共用 fps，秒级边界按实际 fps 换算；每个 Composition 的视频时间从零开始，不能把整篇累计秒数直接当作本片的起点或总长。

各段通常是同一期的讲解片段，默认不重复加频道片头片尾。用户要求章节标题时让它伴随该段口播；整期品牌开场、总结只在适用的首段、末段并且时间预算允许时安排。每段的落定与稳定区优先使用本段总结或已有停顿，不借用下一段，也不为满足默认稳定秒数机械延长视频。

有逐段录音时逐个配对原稿和文件。有整篇录音时，Markdown 分隔线只能确定文本边界，不能证明音频剪辑点；按同版用户确认时码或试听核对每段源音频区间，再绑定或裁取相应音频。不要按字数比例冒充实测切点，不自动切断词句，边界停顿只归入一个区间。需要保留的首尾静音、段间停顿和排除的区间在清单中列明。

整篇录音里的关键词时码转换到独立视频时，只做一次源区间平移和本片音频偏移：

```text
retainedAudioSeconds = sourceAudioEndSeconds - sourceAudioStartSeconds
clipCueSeconds = sourceCueSeconds - sourceAudioStartSeconds + audioStartSeconds
videoEndSeconds = audioStartSeconds + retainedAudioSeconds + extraTailSeconds
```

这里的源时码必须属于该段的源区间；`audioStartSeconds` 是音频在本片中的起点，额外尾段默认零。按每段实际时长注册 Composition，不能把整篇累计结束时间用作后续视频片长。原始录音保持不变，按项目已有媒体方式引用区间或输出独立衍生文件；是否显示字幕仍由项目规则决定。

## 批量实现、编码与验收

在项目正常入口追加全部独立 Composition，Studio 中可以逐段选择预览。每个视频在自己的 Composition 外层放共享背景，并使用本片全局帧驱动；片内跨场景保持连续，每段独立设置结尾稳定区。品牌配置、字体、安全区和语义色统一，内容布局服务各自讲解点。

用户要求编码或交付多个视频文件时，按清单逐个编码到本批次的独立路径，例如 `output/topic-batch/01-expansion.mp4`；可以采用项目已有批量渲染工具。资源允许时并行渲染，但不把创建并行对话或生成旁白作为前提。检查返回结果、每个实际文件的可解码性、帧率与时长；文件路径存在或一次命令启动成功不能证明整批完成。失败段记录原因并单独重试，不将部分成功报告为整批成功。

验收按原稿覆盖、独立产物、逐段时长与口播动作对齐分别检查。抽查每段首个信息画面、核心变化和收尾，并复查最长段的中部进度。所有有效口播段以及用户明确要求的无口播画面按顺序出现且各有独立可播放文件，才满足完整多视频交付；未制作的无口播段在清单中标明。仅要求计划、代码或预览时不擅自扩展编码范围。
