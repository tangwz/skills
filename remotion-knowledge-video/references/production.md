# 制作与验收

## 解释结构

先固定可以回答本期问题的静态最终画面，再让动效解释它如何形成。常用结构不是固定模板数量：

| 关系                 | 适合的图解               |
| -------------------- | ------------------------ |
| 输入经过机制得到输出 | 单流程、对象转换         |
| 两种方案/状态的差异  | 左右对照，匹配尺度与基准 |
| 数量、概率、尺度变化 | 相同坐标系下的变化、分布 |
| 空间、方向、传播关系 | 直接画对象、轨迹与标注   |
| 公式的来历           | 代入、对齐项、逐步推导   |

科学解释的类比标明简化范围；颜色、箭头和数值不能让画面暗示未经支持的因果关系。引述、实验数据和论文图表使用可追溯来源，注明重绘或简化。

## 动效与时间轴

有口播时，先按 [口播与时间轴对齐](narration-timing.md) 建立分段时间预算和讲解词锚点，再安排以下动作。动效时长是可调整的视觉建议，不是独立于口播的片长要求；优先缩短入场、并行呈现独立元素或减少重复演示，不把稿件延长来容纳动效。

整篇逐字稿批量制作时，按 [逐字稿分段与批量输出](batch-transcripts.md) 将分隔线两侧映射到不同的独立视频；本页的场景编排和验收分别在每个视频内执行。片内 `Sequence` 切换不能代替独立 Composition 与输出文件。

新视频默认 60 fps；默认缓动采用 `Easing.bezier(0.16, 1, 0.3, 1)`。时间以秒为基准，实现中按实际 fps 使用 `Math.round(seconds * fps)` 换算。以下帧数仅说明 60 fps 下的对应关系，不直接复制到不同 fps 的项目。

- 常规入场约 0.67–1 秒（40–60 帧），opacity 0→1，位移 18–34px→0，轻缩放 0.96→1。
- 同组元素错开约 0.27–0.6 秒（16–36 帧）；关系线生长约 1–1.73 秒（60–104 帧）；交叉淡化约 0.5 秒（30 帧）。
- 对象出现→关系建立→状态变化→结论落定。一个动画必须能说明一个关系或状态变化。
- Shake 仅用于错误/冲突且幅度小；正常过程不弹跳、不连续旋转。
- 最终结论与片尾均落定，不用无限呼吸或循环充当稳定阅读区。

使用 `Sequence` 时子组件读取的是局部帧。调用父时间轴纯函数时应明确需要全局帧还是局部帧，避免双重减 offset。入场、离场范围均 clamp，不让元素在尾段继续漂移。

将每个场景的 from、duration、对应口播段、关键讲解词出现时间、动作触发/落定时间和稳定区间存为数据。绝对秒级边界统一取整后计算区间长度。复杂状态机、因果依赖或数学计算用纯函数模块，并检查起点、阶段交界和最终帧。口播或录音变化时重算对应段及后续累计边界，不只拉伸总时长。加入片头片尾后重新核算总帧数、音频和媒体结束点。

## 共用组件的接入

1. 找到项目已经安装的品牌层；初次使用才复制模板到 `src/video-brand/`。
2. 使用本地字体 loader 等待字体完成，并将真实 family alias 传入品牌组件。纯字体文件放在 public，字体声明和组件中的 family 必须匹配。
3. 在 Composition 外层放共用背景，在每个场景中放相关标题、图解和品牌标记。内部片头片尾设置 `showBackground={false}`，使移动网格使用全局帧并跨场景连续；外层 `holdSeconds` 指定结尾背景静止时间。模板预览的正文只是用法示例，应替换为本期场景。
4. 用 `Sequence` 编排片头/正文/片尾，依据 Composition fps 换算秒数。默认 2 秒片头为 120 帧、3 秒片尾为 180 帧，12 秒品牌样片共 720 帧；这些是样片与无口播时的起点，不是口播视频必须追加的时长。正片按口播预算调整品牌段，单个讲解片段不自动加这两段。
5. 新作品使用独立内容组件和未占用的 Composition ID，只追加注册，保留已有条目。创建前检查文件名、导出名和 ID；重名时按主题增加变体后缀，不覆盖旧文件。单期独有的时序、素材及渲染输出使用该作品的独立路径。可复查的品牌预览与验证入口保存在目标项目约定的目录，并纳入项目维护；打包缓存可使用临时目录。不改用户已有 Composition 的 ID、帧率或帧长，除非本次明确要求修改该作品。

完整节目共享品牌层，不共享全部场景 DOM。允许直接 SVG、图片、公式与数据可视化表达主题，不为一致性牺牲知识表达。

## 检查方式

采用目标项目现有脚本、包管理器与依赖，先从 `package.json` 确认检查和预览命令。若项目定义了 `lint` 与 `dev` 脚本，可分别使用：

```bash
npm run lint
npm run dev
```

按真实入口路径、Composition ID 与时间轴选择关键帧，输出目录按本次作品独立命名。以下示例假设入口为 `src/index.ts`、Composition ID 为 `EpisodePreview`，时长 12 秒、60 fps；对应 1 秒、6 秒及最后一帧。替换为目标项目的实际值，并确认输出路径不属于旧作品：

```bash
npx remotion still src/index.ts EpisodePreview output/episode-preview/opening.png --frame=60
npx remotion still src/index.ts EpisodePreview output/episode-preview/change.png --frame=360
npx remotion still src/index.ts EpisodePreview output/episode-preview/ending.png --frame=719
```

示例帧必须由实际 Composition 帧数校核。最低检查第一张完整信息画面、核心变化和最终稳定画面；修改品牌组件时另检查 Logo 最宽和最长标题同时出现的场景。移动背景另检查跨场景边界的连续性。证明末尾静止时，逐帧比较整个稳定区的背景与前景，并保留稳定区之前的运动样本；只比较稳定区首尾帧无法排除中间变化。跨帧率同秒比较使用明确的像素差异阈值，避免把不同环境中的字体光栅化差异误判为时序变化。视频动效、转场和声音同步需要 Studio 或片段预览，静帧不能证明这些。

验收关注：字体正确加载、标题换行合理、所有文字在安全区、品牌不占知识焦点、Logo 未拉伸、连接线不穿字、含义与颜色对应、最后一帧稳定。跨场景比较同一身份色和字号，检查换场中间帧是否闪黑或残留。有录音时还要连贯试听开场、中段和结尾，检查逐段锚点及实际媒体结束点；只有稿件时验证预计口播区间与场景预算一致，保留待录音校准的说明。

只对非平凡时间轴、计算或错误处理增加有意义的测试；简单换色和文档更新不增加源码字符串匹配测试。记录现有失败与本次改动的关系，不为通过测试恢复用户已删除的资源。
