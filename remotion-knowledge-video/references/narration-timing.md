# 口播与时间轴对齐

视频总长接近口播时长，且画面沿口播的句意推进。不能先做一组任意时长的动画，再用整体倍速把总长凑到音频；总长相同不能证明中段或关键动作对齐。

整篇逐字稿按分隔线制作多个视频时，先按 [逐字稿分段与批量输出](batch-transcripts.md) 拆分，再逐个应用本页的估时、锚点和验收规则。每个视频独立从零计时；整篇录音时码先换算为对应片内时间，不能沿用整篇累计片长。

## 先确定时间依据

| 输入                             | 用于编排的依据                                               | 交付时的表述                   |
| -------------------------------- | ------------------------------------------------------------ | ------------------------------ |
| 同版录音及词级/句级时码          | 实测语音区间与已核对的讲解词锚点                             | 实测对齐，注明核对范围         |
| 录音，没有时码                   | 实测媒体时长，并通过试听或可用的本地对齐工具定位句意与关键词 | 区分已核对与待核对的锚点       |
| 用户确认的口播时码，没有音频文件 | 按用户提供的总长和锚点编排                                   | 按给定时码对齐，尚未试听       |
| 稿件，没有录音或时码             | 实际念法、个人语速样本与停顿的估算                           | 预计朗读时长与范围，待录音校准 |

用户指定的时长与旧作品修改边界优先。只做视觉适配时保留原时间轴；明确要求音画对齐时才重新排时序。若固定片长与完整口播明显冲突，先说明冲突，给出简化图解、拆分内容或经用户同意调整稿件的选择，不擅自删稿、截断或拉伸音轨。

使用相同稿件与剪辑版本。核对录音是否含开场、总结、首尾静音，以及是否有用户指定的音频偏移。音频与时码冲突时先查版本、偏移和剪辑点；不能以容器时长代替逐段校验。

## 有录音或确认时码

用项目已有媒体工具或 ffprobe 读取实际音频时长；不需要为了测时长新增依赖。保留用户需要的停顿，不自动裁掉首尾静音。没有词级时码时，先听出各语义段的边界，再定位对动画有意义的词，例如“输入”“相加”“归一化”“选出下一个 token”。允许使用环境中已可用的转写或对齐工具，但必须抽查数值、英文缩写和公式，不能把错误转写当作原稿。

音频已经放在某个 `Sequence` 内时，只加一次偏移；内部局部时码与 Composition 全局秒数分开保存。

```text
globalCueSeconds = audioStartSeconds + localCueSeconds
videoEndSeconds = audioStartSeconds + retainedAudioSeconds + extraTailSeconds
```

额外尾段 `extraTailSeconds` 默认是零；只在明确计划了口播之外的画面时增加，并列明用途和秒数。片头前的画面已计入 `audioStartSeconds`，不重复相加。稿内已有开场与结束话术时，品牌与结论画面在这些区间出现；模板的 2 秒片头、3 秒片尾和 12 秒样片不决定正片长度。

## 只有稿件时估算

保留原稿，另外整理用于估时的“实际念法”。标题、镜头说明、Markdown 标记、出处和舞台提示如果不朗读，就不计入；实际会念的开场、总结则必须计入。

- 数字、单位和符号按念法展开，例如 128 维按“一百二十八维”计时，不能只数三个数字。
- 英文单词、缩写和数学表达式按实际读法处理；逐字母念的缩写与一个英文词分开估算。公式按口头解释的完整短句估算，不按 LaTeX 或源码长度估算。
- 图解需要呈现但口播不念的文字不增加朗读时长；必要阅读停顿单独标明。

优先利用同一讲述者、相近知识密度的录音校准语速，或用户已经给出的个人语速。样本语速若按包含停顿的完整朗读时间计算，就不再叠加标点停顿。校准口径与本稿计数口径保持一致；中文多、英文多或公式密集的段落可采用不同局部语速。

没有样本时，先用中文每秒 4 个可读字、英文每秒 2.5 个词作为可调整的工作假设，并单独估算停顿。逗号可暂按 0.2 秒，句末 0.4 秒，段间 0.6 秒；同一个边界取一种停顿，不重复累加。以语速上下浮动约 15% 给出对应的快、慢时长范围。这些是未校准的初估，不是用户实际语速或准确率承诺；公式、新术语等段落应按明确的口头读法和预期停顿修正。

用户明确使用唐师兄频道且没有更可靠的本期时间依据时，可读取 [频道语速参考](speaker-profiles/tang-shixiong.md)，按其口径给出暂定预算与范围。其他频道不默认继承这个个人样本。字幕时轴只能提供代理估计；记录样本区间、实际念法计数、停顿是否已包含及未核对部分，不能仅凭整片时长推断语速。

```text
estimatedSeconds = chineseSpokenCharacters / chineseCharactersPerSecond
                 + englishSpokenWords / englishWordsPerSecond
                 + plannedPauseSeconds
```

逐段求和得到预计口播总长，让预计视频长度与这个中心估计及已声明的额外画面预算一致。不要取最慢估计后再额外加长尾巴，也不要为了套用整秒场景、固定 30/60 秒模板而整体压短。交付说明估时假设、范围与待校准部分；只有文字时不能声称已证明真实音画同步。

## 将口播映射到动作

先按句意拆段，再为每段记录下面这些数据；沿用目标项目的数据格式，不要求特定文件名、组件或接口：

| 数据                     | 用途                           |
| ------------------------ | ------------------------------ |
| 原稿对应句或唯一段落编号 | 能回溯到实际讲解内容           |
| 起止秒数、时间来源       | 区分录音/用户时码与估算        |
| 关键讲解词及其时间       | 锚定核心关系的建立或结果的落定 |
| 对应画面、动作及目标时点 | 明确要对齐的是动作开始还是完成 |
| 停顿、转场和稳定区       | 解释预算，而非隐含加时         |

“先做 A，再做 B，最后得到 C”应按这三个讲解点推进，不在第一句就把结果全部亮出来，也不在口播进入下一步骤后仍演示上一段。独立元素可并行出现，实际有因果依赖的步骤保留顺序。

让动画适应已分配的区间：缩短装饰入场、同时呈现独立元素、保留一个有效计算示例，删去重复回顾与无信息停留。图解过密时减少画面文字或分层显示，不能默认延长整片。不要对整片或所有场景施加统一倍速来代替逐段对齐。

结尾稳定画面可以伴随总结朗读，或使用音频中已有的尾部停顿。确实需要口播后额外阅读区时，只计入一次并说明差值；用户已固定总长时优先在预算内安排。缩短作品的稳定区需让背景与前景一起调整，并满足模板的合法时长约束；不静默缩短用户明确指定的停留时间。

## 帧换算与检查

内部场景与动作按实际共用 fps 四舍五入全局绝对边界，从相邻边界求时长，避免各段分别取整后累积偏差。录音的最终覆盖帧数从实际挂载起始帧加上音频与已声明尾段的帧跨度：跨度先消除正整数边界附近数个浮点精度单位的误差，再向上取整，保证最后不足一帧的声音也被覆盖。不要把整数起点换回秒后再相乘，或先用未取整的偏移计算总长；不能用固定毫秒容差把真实尾音吸附掉。

```ts
function ceilFrameSpan(seconds: number, fps: number) {
  const frames = seconds * fps;
  const nearest = Math.round(frames);
  const tolerance = 4 * Number.EPSILON * Math.max(1, Math.abs(frames));
  const stableFrames =
    nearest > 0 && Math.abs(frames - nearest) <= tolerance ? nearest : frames;
  return Math.ceil(stableFrames);
}

const startFrame = Math.round(startSeconds * fps);
const endFrame = Math.round(endSeconds * fps);
const durationInFrames = endFrame - startFrame;
const cueFrame = Math.round(globalCueSeconds * fps);
const audioStartFrame = Math.round(audioStartSeconds * fps);
const placedAudioEndSeconds = audioStartFrame / fps + retainedAudioSeconds;
const totalFrames =
  audioStartFrame + ceilFrameSpan(retainedAudioSeconds + extraTailSeconds, fps);
```

例如 `31 / 60` 秒在 60 fps 下就是 31 帧，不能因乘积的浮点噪声变成 32 帧；真正超出帧边界的音频或尾段仍应向上补足一帧。正的不足一帧跨度也不能吸附为零。

若片尾视觉还有单独的已声明结束边界，取它与音频覆盖帧数的最大值。只有稿件时总长可四舍五入中心估计，最后一个场景结束于注册总帧数。有录音时，最后场景也使用最终覆盖帧数，不能继续停在四舍五入的旧总长。音频子 `Sequence` 的可见区间与裁取设置同样应覆盖保留的音频，不能只延长空白视频。

遇到同帧短段时合并视觉区间或共享画面，不为每个短词强行创建一个 `Sequence`。修改段落或换用录音时重算该段和后续边界；只改最后的总帧数不能修正中间漂移。可通过项目支持的元数据计算入口按实际音频时长注册 Composition，或者让同一份时序数据决定注册帧数和场景，避免维护两套总长。

- **总长**：以实际挂载起点、保留音频时长与已声明额外画面预算核对；覆盖结束时点的向上取整误差小于一个视频帧。音频挂载点相对用户秒级偏移的四舍五入误差另行记录，通常不超过半帧。额外画面时间不能用来掩盖无信息拖尾。只有稿件时按估算中心核对预算，不把它称为实测误差。
- **进度**：检查所有场景边界和关键讲解词；至少连贯复查开场、中段、结尾。已确认锚点与其指定的动作目标默认相差不超过 0.3 秒；项目或用户更严格时采用其要求。此容差用于动作目标，不要求整个复杂动画在 0.3 秒内结束。
- **结尾**：总结期间画面已经落定，保留最后一句和所需停顿，音频不被 Composition 截断；没有重复追加片头、片尾或静止阅读时间。

有音频时用 Studio 或带音轨的片段试听，静帧、容器时长和状态测试都不能证明声音同步。按给定时码做检查时注明未试听；未能使用录音验证的部分明确标为待核对。交付逐段时序表、时间依据、口播时长、视频时长、差值与差值来源，说明录音到位后哪些估算需要替换。

编码验收同时检查视频流、音频流和容器时长；AAC 填充或编码延迟可能使它们不同。不要把编码后的延迟反向加入口播内容预算，也不能只测视频流便断言音轨没有截断。发现信号位移或尾音异常时，定位输入裁取、混音与最终编码步骤；项目支持时可保留无损混音后一次编码最终音轨，再核对成片中的开头和末尾。
